# Роадмап: спецификация вкладок «По месяцам» и «По кварталам»

Документ для переноса приложения в архитектуру «логика в БД, фронт — тонкий клиент».

Описаны:
- все кнопки и интерактивные элементы;
- пользовательские действия и ожидаемый результат;
- бизнес-правила и расчёты, которые сейчас выполняются на фронте;
- текущие HTTP API (ориентир для процедур/функций в БД).

Источник: `frontend/src/components/views/HorizontalView.vue`, `QuartersView.vue`, общие компоненты `Block.vue`, `TaskItem.vue`, `ModalEditBlock.vue`, `TaskCardModal.vue`, composables `useBlocks`, `useTasks`, `useDates`, `useDragLines`.

---

## 1. Общая модель данных

### 1.1. Проект и этап (block / stage)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string/number | Идентификатор этапа |
| `projectId` | string | Проект, к которому относится этап |
| `title` | string | Название этапа |
| `description` | string | Описание |
| `startDate` | date (ISO `YYYY-MM-DD`) | Дата начала этапа |
| `releaseDate` | date (ISO `YYYY-MM-DD`) | **Ключевая дата для позиционирования** на шкале «по месяцам» / «по кварталам» |
| `effort` | number | Трудозатраты этапа, часы (0–1000) |
| `completed` | boolean | Флаг завершённости (legacy, основной статус — по задачам) |
| `ownerUsername` | string | Владелец этапа |
| `tasks` | array | Список задач этапа |

### 1.2. Задача (task)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Идентификатор задачи |
| `title` | string | Название |
| `status` | enum | `todo` → `progress` → `done` (циклическое переключение) |
| `order` | number | Порядок внутри этапа |
| `linkUrl` | string | Внешняя ссылка |
| `linkNote` | string | Примечание к ссылке |
| `startDate` | date | Дата начала (опционально, для таблицы/Ганта) |
| `releaseDate` | date | Дата окончания (опционально) |
| `effort` | number | Оценка, часы |
| `predecessorIds` | string[] | Legacy: id предшественников в том же этапе (FS) |
| `predecessorLinks` | object[] | Расширенные связи: `{ predId, type: FS\|SS\|FF\|SF, lagDays }` |

### 1.3. Текущие API (этапы)

| Метод | Endpoint | Назначение |
|-------|----------|------------|
| GET | `/api/blocks?projectId={id}` | Список этапов активного проекта |
| POST | `/api/blocks` | Создание этапа |
| PUT | `/api/blocks/:id` | Полное обновление этапа (включая массив `tasks`) |
| DELETE | `/api/blocks/:id` | Удаление этапа |

> Сейчас почти все операции с задачами идут через **PUT всего этапа**. При переносе в БД логично выделить отдельные процедуры на задачу, но контракт должен сохранить те же правила.

## 2. Общие элементы шапки (для обеих вкладок)

Показываются при `viewMode = horizontal` или `quarters`.

### 2.1. Кнопки панели инструментов

| Наименование | Условие видимости | Действие | Логика / API |
|--------------|-------------------|----------|--------------|
| **По месяцам** | Вкладка навигации | Переключение вида | `viewMode = horizontal` |
| **По кварталам** | Вкладка навигации | Переключение вида | `viewMode = quarters` |
| **+ Новый этап** | Не read-only | Создать этап | `POST /api/blocks`. Даты: если есть этапы — `startDate` = `releaseDate` последнего по дате окончания, `releaseDate` = +1 месяц; иначе — текущий месяц. `effort = 40`, `title = "Новый этап {timestamp}"`, `projectId` = активный проект |
| **📸 PNG** | Не read-only | Экспорт скриншота | Клиентский `html2canvas` (не БД) |
| **📄 PDF** | Не read-only | Экспорт PDF | Клиентский (не БД) |

### 2.2. Блок статистики (над контентом)

| Показатель | Расчёт (сейчас на фронте) |
|------------|---------------------------|
| Этапов | `count(blocks)` |
| Завершено | Этапы, у которых **все** задачи `status = done` |
| В работе | Этапы с хотя бы одной задачей `progress` или `todo` |
| Всего задач | Сумма `tasks.length` по этапам |
| Задач выполнено | Сумма задач со `status = done` |
| Прогресс | `round(completedTasks / totalTasks * 100)` % |

> Рекомендация для БД: отдельное представление/функция агрегатов по `projectId`.

### 2.3. Переключатель проекта

| Элемент | Действие |
|---------|----------|
| Выпадающий список проектов | `GET /api/projects`, смена активного → перезагрузка `GET /api/blocks?projectId=...` |

## 3. Вкладка «По месяцам» (`HorizontalView`)

### 3.1. Назначение

Горизонтальная шкала **месяцев**. Этапы размещаются в колонке месяца по полю `releaseDate`, внутри месяца — вертикальной «стопкой» без наложений.

### 3.2. Элементы шкалы (не кнопки, но важны для БД)

| Элемент | Описание |
|---------|----------|
| Заголовок месяца | Метка (`Январь 2026`) + число дней в месяце |
| Линии дней | Вертикальная сетка по дням |
| Линии начала/конца месяца | Визуальные границы |
| **Сегодня** | Красная вертикальная линия на текущей дате |

### 3.3. Кнопки и интерактивные зоны шкалы

| Наименование | Где | Действие | Логика |
|--------------|-----|----------|--------|
| **▸ Показать следующий пустой месяц** | На последнем видимом месяце, если после него нет этапов | Расширить шкалу на 1 пустой месяц | UI-состояние `trailingEmptyMonthsCount` (localStorage не используется для этого). **Только отображение**, данные не меняются |
| **‹ Скрыть пустой месяц** | На последнем месяце, если он пустой | Свернуть trailing-пустой месяц | UI-состояние |
| **Ручка изменения ширины месяца** | Правый край ячейки месяца в шапке | Drag → изменить ширину колонки | Пересчёт `globalDayWidth` в localStorage (`put-roadmap.horizontal.globalDayWidth.v1`). **Только UI** |
| **Сбросить ширину месяцев** (иконка ↺) | Левый верх шапки, если ширина менялась | Вернуть дефолтную ширину | Сброс localStorage, учёт минимальной ширины под самый широкий блок |

### 3.4. Вертикальная линия даты этапа (timeline-line)

| Наименование | Тип | Действие | Логика / API |
|--------------|-----|----------|--------------|
| **Линия с датой** (синяя, от шапки к карточке) | Drag | Перетаскивание по шкале дней | При отпускании: `PUT /api/blocks/:id` с новым `releaseDate`. Позиция X → дата через привязку к видимым дням. Превью даты во время drag — только UI |
| **Метка даты на линии** | Drag | То же | То же |

**Правила при смене месяца через линию:**
- Если этап переносится в другой месяц, вертикальная позиция (`positionInMonth`) пересчитывается: ставится под последним этапом в целевом месяце + отступ.

### 3.5. Карточка этапа (компонент `Block.vue`)

Общая для «По месяцам» и «По кварталам».

| Наименование | Действие | Логика / API |
|--------------|----------|--------------|
| **Заголовок этапа** (клик) | Открыть модалку «Редактировать этап» | `emit('editBlock')` → `ModalEditBlock` |
| **Шапка этапа** (drag) | Начало перетаскивания этапа | В «По месяцам»: `onBlockDragStart` (DnD data `type: block`). **Полноценный drop этапа на шкале не реализован** — только визуальный drag |
| **Иконка приоритета** (●/◆/▲/❗) | Только отображение | По `block.effort`: <40 low, <80 medium, <120 high, иначе critical |
| **+** (Добавить задачу) | Создать задачу и открыть карточку | `addTask` → `PUT /api/blocks/:id`. Новая задача: `title="Новая задача"`, `status=todo`, `order=last`, `predecessorIds=[]` |
| **Статус задачи** (○ / 🕛 / ✅) | Цикл статуса | `todo → progress → done → todo`. Optimistic UI + `PUT /api/blocks/:id` |
| **Название задачи** (клик) | Открыть `TaskCardModal` | — |
| **Иконка ссылки** у задачи | Открыть URL в новой вкладке | Только клиент, если `linkUrl` задан |
| **Drag задачи** (за иконку статуса) | Перестановка / перенос | См. раздел 3.6 |
| **Дата окончания этапа** (📅, клик) | Inline-редактор даты | `releaseDate` → `PUT /api/blocks/:id` через `updateBlockDate` |
| **Прогресс этапа** | Только отображение | `% = doneTasks / totalTasks * 100` |
| **Трудозатраты** | Только отображение | `block.effort` / сумма `task.effort` |

**Цвет фона карточки этапа** (`getBlockBackgroundColor`):
- Нет задач → `#C0C0C0`
- Все задачи `done` → `#90EE90`
- Есть `progress` или `done`, но не все → `#87CEEB`
- Иначе → `#C0C0C0`

**Вертикальная укладка в месяце** (логика для БД при отображении):
- Этапы в одном месяце сортируются по `releaseDate`
- `top` первого = 30px
- Каждый следующий: `top += height(предыдущего) + 190px`
- `height` = max(расчётная, измеренная в DOM) + 18px × число задач

### 3.6. Drag & Drop задач

| Сценарий | Действие | Логика / API |
|----------|----------|--------------|
| Drop на другую задачу **в том же этапе** | Вставить перед целевой | Пересчёт `order`, `PUT /api/blocks/:id` |
| Drop в пустую зону списка **в том же этапе** | В конец списка | `order = last`, `PUT` |
| Drop в **другой этап** | Перенос задачи | Удалить из source, вставить в target, пересчитать `order` в обоих; очистить `predecessorIds` / `predecessorLinks`, ссылающиеся на несуществующие id; **два** `PUT` (source и target) |

### 3.7. Модалка «Редактировать этап» (`ModalEditBlock`)

Открывается по клику на заголовок этапа.

| Поле / кнопка | Действие | API |
|---------------|----------|-----|
| Название этапа | Редактирование | — |
| Описание | Редактирование | — |
| Дата начала / окончания | Редактирование | — |
| Трудозатраты (слайдер 0–1000) | Редактирование | — |
| Владелец этапа | Выбор из списка пользователей | `GET` users (в модалке) |
| Проект | Выбор проекта | При смене этап может исчезнуть из текущего списка |
| **+ Добавить задачу** | Добавить в список модалки | Локально, сохраняется по «Сохранить» |
| Статус задачи в модалке | Цикл `todo/progress/done` | Локально |
| Клик по названию задачи | Inline-редактирование названия | Локально |
| **Редактировать** (карандаш) | Панель: ссылка, даты, часы | Локально |
| **🗑️** у задачи | Удалить задачу | Локально + очистка зависимостей |
| **Очистить ссылку** | `linkUrl = ''` | Локально |
| **Удалить** (этап) | Удаление этапа | `DELETE /api/blocks/:id` |
| **Отмена / Закрыть** | Закрыть без сохранения | — |
| **Сохранить** | Сохранить этап и все задачи | `PUT /api/blocks/:id`. Нормализация: даты задач в пределах дат этапа, `effort >= 0`, `linkUrl` с `https://` |

### 3.8. Модалка «Редактирование задачи» (`TaskCardModal`)

| Поле / кнопка | Действие | API |
|---------------|----------|-----|
| Название задачи | Редактирование | — |
| Ссылка | Редактирование + кнопка открыть | — |
| Дата начала / окончания | В пределах дат этапа | `startDate <= releaseDate` |
| Оценка часов | number ≥ 0 | — |
| **Очистить ссылку** | Сброс `linkUrl` | — |
| **Удалить** | Удалить задачу | `PUT` этапа без задачи |
| **Отмена** | Закрыть | — |
| **Сохранить** | `saveTaskCard` | `PUT /api/blocks/:id` |

## 4. Вкладка «По кварталам» (`QuartersView`)

### 4.1. Назначение

Горизонтальная шкала **кварталов** (Q1–Q4). Этапы группируются по кварталу даты `releaseDate`, внутри квартала — вертикальная стопка.

### 4.2. Отличия от «По месяцам»

| Функция | По месяцам | По кварталам |
|---------|------------|--------------|
| Шкала | Месяцы + дни | Кварталы (фикс. ширина 360px) |
| Линия «Сегодня» | Есть | **Нет** |
| Drag линии даты | Есть | **Нет** |
| Ресайз ширины колонки | Есть | **Нет** |
| Trailing пустой период | Есть | **Нет** |
| Drag этапа за шапку | Частично (start без drop) | **Нет** (не подключён `block-drag-start`) |
| Карточка этапа, задачи, модалки | Да | Да (тот же `Block.vue`) |

### 4.3. Элементы шкалы

| Элемент | Описание |
|---------|----------|
| Заголовок квартала | `Q{n} {year}` + подпись (`янв-мар`, `апр-июн`, …) |
| Разделитель квартала | Вертикальная линия справа от колонки |

**Базовый год шкалы:** `2026` (`BASE_YEAR`).  
Индекс квартала: `(year - BASE_YEAR) * 4 + floor(month / 3)`.

Видимый диапазон: от минимального до максимального квартала среди этапов с `releaseDate`.

### 4.4. Позиционирование этапов (логика для БД)

| Правило | Значение |
|---------|----------|
| Горизонталь | Центр этапа в колонке квартала, ширина ≈ 90% колонки (макс. `QUARTER_WIDTH - 10`) |
| Сортировка в квартале | По `releaseDate` ascending |
| Стартовый `top` | 20px |
| Высота блока | `max(estimate, measured)` + буфер 5% (6–16px) + `18px × tasksCount` |
| Отступ между блоками | `clamp(round(height * 0.055), 12, 40)` px |
| Следующий `top` | `top + height + gap` |

### 4.5. Кнопки и действия

Все действия в карточке этапа, модалках этапа/задачи и DnD задач — **идентичны разделу 3.5–3.8**.

Дополнительно в «По кварталам»:

| Наименование | Действие | Логика |
|--------------|----------|--------|
| **Дата окончания** (inline в карточке) | Изменить `releaseDate` | Может **переместить этап в другой квартал** → пересчёт `positionInQuarter` |

**Нет** отдельных кнопок на уровне вкладки — только скролл шкалы (синхронизация шапки и контента).

## 5. Сводная таблица операций (кандидаты в процедуры БД)

| ID | Наименование операции | Триггер UI | Входные данные | Результат |
|----|----------------------|------------|----------------|-----------|
| `STAGE_LIST` | Получить этапы проекта | Открытие вкладки / смена проекта | `projectId` | Список этапов с задачами, отсортированными по `order` |
| `STAGE_CREATE` | Создать этап | «+ Новый этап» | `projectId`, опц. даты | Новый этап с дефолтами |
| `STAGE_UPDATE` | Обновить этап | Сохранить в модалке | Поля этапа + `tasks[]` | Обновлённый этап |
| `STAGE_DELETE` | Удалить этап | Удалить в модалке | `stageId` | Этап удалён |
| `STAGE_SET_RELEASE_DATE` | Изменить дату релиза | Линия даты / inline дата | `stageId`, `releaseDate` | Обновлён этап; **пересчёт позиции** в месяце/квартале |
| `TASK_ADD` | Добавить задачу | «+» в карточке / модалке | `stageId` | Задача в конце списка |
| `TASK_UPDATE` | Обновить задачу | TaskCardModal / модалка этапа | `stageId`, `taskId`, patch | Обновлённая задача |
| `TASK_DELETE` | Удалить задачу | Удалить в модалке | `stageId`, `taskId` | Задача удалена; зависимости очищены |
| `TASK_CYCLE_STATUS` | Сменить статус | Клик по статусу | `stageId`, `taskId` | `todo→progress→done→todo` |
| `TASK_REORDER` | Переставить в этапе | DnD | `stageId`, `taskId`, `targetOrder` / `targetTaskId` | Новый `order` |
| `TASK_MOVE` | Перенести между этапами | DnD | `sourceStageId`, `targetStageId`, `taskId`, позиция | Два этапа обновлены |
| `STATS_PROJECT` | Статистика проекта | Шапка | `projectId` | Агрегаты (см. §2.2) |
| `LAYOUT_MONTH` | Раскладка по месяцам | Отрисовка «По месяцам» | этапы + `releaseDate` + высоты | `left`, `top`, `width` для каждого этапа |
| `LAYOUT_QUARTER` | Раскладка по кварталам | Отрисовка «По кварталам» | этапы + `releaseDate` + высоты | `left`, `top`, `width` для каждого этапа |

## 6. Что остаётся на фронте (тонкий клиент)

- Переключение вкладок и скролл шкалы
- Ресайз ширины месяцев, trailing-пустые месяцы (localStorage)
- Линия «Сегодня», сетка дней, визуальные разделители
- Drag-preview (линия даты, hover при DnD)
- Экспорт PNG/PDF
- Открытие внешних ссылок задач
- Режим read-only (гость): скрытие кнопок редактирования

---

## 7. Роли и ограничения

| Условие | Поведение |
|---------|-----------|
| `isReadOnly = true` | Нет создания/редактирования/удаления, DnD заблокирован |
| Нет `activeProjectId` | Список этапов пуст, «+ Новый этап» → ошибка «Сначала выберите проект» |
| Смена `projectId` у этапа | Этап исчезает из текущего проекта после сохранения |
